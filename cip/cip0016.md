## Summary

Introduce a minimal GitHub Actions workflow that, on pull requests (and pushes to `main`), creates a clean Python environment, installs `pub-dialogue` with the `dev` extra, and runs `pytest`. This implements [REQ-0009](../requirements/req0009_pr-automated-tests.md): PRs are gated on an automated suite without requiring the PDF corpus or API keys.

**Which requirements does this CIP address?** `related_requirements: ["0009"]`.

## Motivation

PR [#2](https://github.com/mlatcl/pub-dialogue/pull/2) (CIP-0015) triggered no checks because the repository has no `.github/workflows/`. Tests exist under `tests/` and were run locally, but merge confidence depends on voluntary local runs. A small CI workflow closes that gap before further package changes accumulate.

## Detailed Description

### Scope (in)

- One workflow file, e.g. `.github/workflows/ci.yml`.
- Triggers: `pull_request` to `main`, and `push` to `main` (so post-merge failures are visible).
- Job steps:
  1. Checkout
  2. Set up Python (start with one version matching `requires-python`, e.g. 3.11; optional matrix later)
  3. `pip install -e ".[dev]"` — must succeed with git dependencies (`lynguine[documents]`, and any others declared in `pyproject.toml`). Requires `allow-direct-references` already present for Hatch.
  4. `pytest` (default `testpaths` from `pyproject.toml`)
- Brief contributor note in `README.md` or `SETUP.md`: how to run the same command locally.

### Scope (out)

- Running analysis notebooks end-to-end
- Checking out or caching the full `data/` PDF corpus
- OpenAI / litellm live calls (tests that need network LLM APIs stay mocked or skipped)
- Full branch-protection admin UI (document that maintainers should mark the workflow required; enabling protection may need org permissions)

### Design choices

| Choice | Decision | Rationale |
|--------|----------|-----------|
| Host | GitHub Actions | Repo is on GitHub; no existing CI elsewhere |
| Suite | Existing `pytest` under `tests/` | Enough for a first gate; expand coverage in later CIPs |
| Corpus smoke | Not in CI | Large binaries / local paths; keep `scripts/chunking_report.py` as optional local smoke |
| Python versions | Single version first | Faster green path; matrix (3.10–3.12) as a follow-on if useful |
| Secrets | None required | Install and unit/integration tests only |

### Failure modes to handle in the workflow

- Git dependency clone failures: fail the job with clear pip logs (no silent skip).
- Flaky network: default Actions retry is enough for v1; pin lynguine to a commit/tag later if `main` breaks installs.

## Implementation Plan

1. **Add workflow** — `.github/workflows/ci.yml` with checkout, setup-python, install, pytest.
2. **Docs** — one short subsection in README or SETUP: “CI runs `pytest`; locally: `pip install -e '.[dev]' && pytest`”.
3. **Verify** — push on a branch / open a draft PR and confirm the check appears and passes; optionally open a deliberate failing PR to confirm red.
4. **Branch protection (manual)** — recommend requiring the CI job on `main` once green once.

## Backward Compatibility

No package API changes. Contributors need network on first CI/local install for git dependencies (already true after CIP-0015).

## Testing Strategy

- The workflow itself is validated by observing a green run on a PR.
- No new Python tests required for the YAML; keep the job definition minimal and readable.
- If install becomes slow, cache pip in a later iteration — not required for v1.
