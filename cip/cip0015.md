# CIP-0015: Adopt lynguine document access for PDF chunking

> **Note**: CIPs describe HOW to achieve requirements (WHAT).

## Summary

Replace the in-tree PDF chunker (`pub_dialogue.access.extract_chunks_from_pdf` and its helpers) with **direct** calls to lynguine’s CIP-0013 document access API (`lynguine.access.documents.segment_pdf` / `segment_pdf_frame`, strategy `pub_dialogue.v1`). No compatibility shim that re-implements or wraps the old function signature — analyses standardise on the shared access contract.

This follows lynguine CIP-0013 (merged): apps adopt `document_segment` / `segment_pdf` incrementally and keep research prompts/clustering locally.

## Motivation

- The chunker was the seed for lynguine `pub_dialogue.v1`; keeping a second copy drifts and doubles maintenance.
- We want the same access piece across analyses (pub-dialogue, dialogue-formats, mlresearch follow-ons).
- Install cost of `lynguine[documents]` is accepted.

## Detailed Description

### Target call pattern (no wrap)

Notebooks and scripts call lynguine directly:

```python
from lynguine.access.documents import segment_pdf_frame

chunks_df = segment_pdf_frame(
    str(pdf_path),
    strategy="pub_dialogue.v1",
    aspect="body_chunks",
    allowed_roots=[str(pdf_folder.resolve())],
    min_chunk_words=40,
    min_chunk_chars=80,
    max_chunk_words=500,
    # optional chrome cleanup once regenerating artefacts:
    # filter_chrome=True,
)
```

Metadata (`technology`, `year`) is **joined after** segmentation from the existing metadata table — lynguine units do not carry research labels. That keeps access corpus-agnostic.

Typical post-join:

```python
units = segment_pdf_frame(...)
units["source_file"] = Path(units["source_path"]).map(lambda p: Path(p).name)  # if basename needed
chunks_df = units.merge(metadata_df, left_on="source_file", right_on=..., how="left")
```

Prefer adopting lynguine column names (`unit_id`, `source_path`, `segment_strategy`, `chunking_method`, …) in new artefact writes. Where checkpoints key on `chunk_id` / `source_file`, either:

1. regenerate artefacts under the new grain, or
2. derive `chunk_id = unit_id` (or a stable hash) and `source_file = Path(source_path).name` in the notebook only — not inside `pub_dialogue.access`.

### What leaves `pub_dialogue.access`

Delete (or move to tests-only fixtures if still needed for golden comparisons during migration):

- `extract_chunks_from_pdf`
- `_extract_paragraphs_from_blocks`, `_paragraph_split`, `_split_into_sentences`, `_repack_sentences_into_chunks`
- `_coverage`, `_word_count`, `_ocr_text` (see OCR below)
- chunk-stats accumulator (`reset_chunk_stats` / `get_chunk_stats` / `_doc_diagnostics`) unless still useful for a thin lynguine-based report script

Keep: `load_artifacts`, checkpoint I/O, `AccessStage` for **paths and analysis config** (output/checkpoint/pdf folders). `AccessStage` may expose lynguine strategy params as fields, but must not re-export a local chunker.

Re-exports in `pub_dialogue.utils` / `__init__` for `extract_chunks_from_pdf` are removed (breaking change; see Backward Compatibility).

### Dependency

Add to `pyproject.toml`:

```toml
"lynguine[documents] @ git+https://github.com/lawrennd/lynguine.git"
```

(or a pinned tag/commit once preferred). PyMuPDF remains available transitively via the `documents` extra; we can drop the direct `PyMuPDF` dependency once nothing else imports `fitz` in this package.

### OCR / sparse text

lynguine v1 detects sparse/absent text layers and errors by default (`on_sparse_text="error"`). pub-dialogue’s `ocr_if_image_only` path is **not** ported into a wrap.

Policy for this CIP:

- Default pipeline: `on_sparse_text="warn"` (or `"error"` if we prefer hard fail) and record sparse PDFs in the data-quality notebook — same honesty as lynguine.
- OCR remains a **follow-on** (lynguine backlog OCR strategy, or a separate pub-dialogue preprocess that produces a text PDF / sidecar before calling `segment_pdf`). Do not reintroduce OCR inside `access.py` as a second chunker.

### Chrome filters

Parity mode (`filter_chrome=False`, lynguine default) matches the seeded chunker for regenerating comparable tables. Once artefacts are regenerated intentionally, notebooks may set `filter_chrome=True` for cleaner Ipsos/Ada-style chrome. That is a data decision, not a compatibility shim.

### AccessStage (CIP-0010)

Update fields to lynguine-oriented knobs (`strategy`, `on_sparse_text`, chunk floors) and drop `ocr_if_image_only` from the stage defaults (or leave deprecated with a clear error pointing at the follow-on). No `access.extract_chunks_from_pdf(...)` method.

### Diagnostics

`scripts/chunking_report.py` should call `segment_pdf` / `read_pdf` + `document_features` instead of the local chunker, or be rewritten as a small lynguine-based report. Module-level `_chunk_stats` can die with the chunker.

## Implementation Plan

1. **Dependency** — add `lynguine[documents]`; verify install in a clean venv; update `SETUP.md` / README if the git dependency needs a note.
2. **Strip local chunker** — remove chunking helpers and `extract_chunks_from_pdf` from `access.py`; clean `__init__.py` / `utils.py` exports.
3. **AccessStage** — retarget config fields; document the lynguine call pattern in the module docstring.
4. **Notebooks / scripts** — update `01_processing.ipynb`, `00_data_quality.ipynb`, `01a_clustering.ipynb` imports/cells, and `scripts/chunking_report.py` to call `segment_pdf_frame` (or `segment_pdf`) and join metadata.
5. **Tests** — replace chunker unit tests that mock `fitz` internals with tests that either (a) use lynguine synthetic fixtures / small committed PDFs via `segment_pdf`, or (b) assert the package no longer owns a local chunker and that imports resolve. Drop OCR-in-chunker tests or mark as follow-on.
6. **Smoke** — run chunking over `pdfs/` (or `data/`) and compare unit counts / methods to a saved baseline under parity settings; decide whether to regenerate `outputs/paragraph_chunks.csv`.

## Backward Compatibility

**Breaking** for anyone importing `pub_dialogue.access.extract_chunks_from_pdf` or relying on its list-of-dicts schema (`source_file`, `technology`, …).

- Old notebooks that inlined the chunker (v12/v19 archives) are left untouched as historical artefacts.
- Active numbered notebooks must be updated in this CIP.
- Checkpoint / CSV artefacts keyed on old `chunk_id` values may need regeneration after the cutover.

No long-lived adapter function in `pub_dialogue.access`.

## Testing Strategy

- Unit: package imports; `AccessStage` still loads artefacts; no `extract_chunks_from_pdf` symbol.
- Integration: one synthetic or fixture PDF through `segment_pdf_frame` with `pub_dialogue.v1` and `allowed_roots`.
- Optional local smoke: corpus chunk counts under parity params vs previous baseline.
