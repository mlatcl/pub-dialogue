## Summary

Comparing two pipeline runs revealed that the LLM-generated framing lens step
produces different lens names and cluster groupings on each run, causing the
AI-vs-privacy distinctiveness figure to reverse direction between runs. This
CIP treats the framing lens mapping as a committed research design decision
(rather than a stochastic pipeline output) by introducing a canonical mapping
file, and adds a lens-scheme sensitivity section to the robustness notebook to
characterise how variable the finding is across plausible lens groupings.

**Related requirement**: REQ-0007 (Framing lens assignments are stable and their variability is characterised)

## Motivation

The pipeline produces framing lenses by calling an LLM (cells 27–28 for concerns,
66–67 for benefits in `public_dialogue_analyser_v19.ipynb`) with a free-form
prompt:

> *"Group these clusters into 8–12 higher-level FRAMING LENSES… Name (2–4 words)"*

Each call may produce different lens names and assign the same clusters to
different groups. In a comparison between two runs:

- Run A (sketch document): AI over-indexed on a "Privacy, Consent & Data" lens
  by **+16.7pp** — the paper's central claim.
- Run B (current `outputs/`): AI **under-indexed** on a "Privacy and Data
  Security" lens by **−4.5pp** — opposite direction.

The reversal is not due to k-means stochasticity; `RANDOM_SEED = 42` is
already set and used in all `KMeans(...)` calls in both the main and robustness
notebooks. The instability lives entirely in the lens-grouping LLM step.

The existing robustness notebook already addresses k-sensitivity (Section 10)
and prompt-sensitivity (Section 10C), but does not test lens-scheme sensitivity.
The paper's Supplementary Table S1 therefore has a gap that this CIP fills.

Note: the k-sensitivity section's descriptive text (cell 20 in
`05_robustness.ipynb`) still references "Privacy/Consent/Data" and
"Safety/Health/Environment" — the old lens names — and will need updating to
be consistent with the canonical scheme introduced here.

## Detailed Description

### Architecture of the problem

`public_dialogue_analyser_v19.ipynb` is the legacy monolith. The live pipeline
is the numbered notebooks, which delegate all logic to `pub_dialogue/address.py`
via the `AddressStage` façade (CIP-0010).

```
01_processing.ipynb
  Cell 33:  extract_phrases() → concerns_df                           [deterministic with fixed seed ✓]
  Cell 41:  generate_embeddings() → concern_embeddings                [deterministic ✓]

01a_clustering.ipynb
  Cell 22:  _address.cluster_phrases(kind='concern')
              → KMeans(random_state=RANDOM_SEED) in address.py        [deterministic ✓]
  Cell 34:  _address.label_clusters() → cluster_labels_dict           [deterministic ✓, run once]
  Cell 36:  _address.assign_framing_lenses(kind='concern')
              → LLM lens-grouping in address.py                        [stochastic ✗ — not seeded]
              → writes outputs/framing_lens_mappings.json
  Cell 54:  _address.assign_framing_lenses(kind='benefit')            [stochastic ✗ — not seeded]
              → writes outputs/benefit_framing_lens_mappings.json

05_robustness.ipynb
  Cell 1:   load_artifacts() → loads framing_lens_mappings from outputs/
```

`assign_framing_lenses()` in `pub_dialogue/address.py` already has a partial
cache: it checks whether `outputs/framing_lens_mappings.json` exists and, if
coverage is complete, returns it without calling the LLM. However, the cache is
in the `outputs/` directory, which is not committed to git. A fresh environment
(or a run after clearing outputs) always calls the LLM, producing a new and
potentially different lens scheme.

The fix is entirely in `pub_dialogue/address.py` — the notebook cells (36 and 54
in `01a_clustering.ipynb`) are thin wrappers that will inherit the new behaviour
automatically.

### Part A: Canonical lens mapping file

Introduce two committed JSON files following the same pattern as CIP-0012's
`pub_dialogue/prompts.yml`:

- `pub_dialogue/lens_mapping_canonical.json`
- `pub_dialogue/benefit_lens_mapping_canonical.json`

These files contain the approved cluster-to-lens mapping. They are:
- Committed to git after a deliberate review step
- Not auto-generated on every run
- Updated only when the research design intentionally changes

**Change to `assign_framing_lenses()` in `pub_dialogue/address.py`:**

The method currently has this cache lookup at the top:

```python
prefix = "benefit_" if kind == "benefit" else ""
out_file = output_folder / f"{prefix}framing_lens_mappings.json"
if out_file.exists():
    with open(out_file) as f:
        cached = json.load(f)
    covered = {cid for v in cached.values() for cid in v.get("cluster_ids", [])}
    if covered >= set(range(n_clusters)):
        return cached
```

Add a canonical-file check **before** this outputs-cache check. The canonical
file lives in `pub_dialogue/` (alongside `prompts.yml`) and is resolved relative
to the package directory:

```python
import logging
from pathlib import Path as _Path

# Canonical committed mapping (takes priority over run-output cache)
_pkg_dir = _Path(__file__).parent
prefix = "benefit_" if kind == "benefit" else ""
canonical_path = _pkg_dir / f"lens_mapping_canonical_{kind}.json"

if canonical_path.exists():
    logging.info("assign_framing_lenses: loading canonical %s lens mapping from %s", kind, canonical_path)
    with open(canonical_path) as f:
        return json.load(f)

# Run-output cache (existing behaviour)
out_file = output_folder / f"{prefix}framing_lens_mappings.json"
if out_file.exists():
    ...  # existing cache logic unchanged

# LLM call (existing behaviour) — after which we warn:
...  # existing LLM logic unchanged
logging.warning(
    "assign_framing_lenses: no canonical %s lens mapping found. "
    "Generated from LLM and written to %s. "
    "Review this file and copy it to pub_dialogue/lens_mapping_canonical_%s.json "
    "to make the mapping stable across runs.", kind, out_file, kind
)
```

File naming uses `lens_mapping_canonical_concern.json` and
`lens_mapping_canonical_benefit.json` (kind-suffixed) to keep them distinct and
make the `kind` parameter explicit in the filename.

### Part B: Lens-scheme sensitivity section in robustness notebook

Add a new section **SECTION 10D: M6(e) Lens-scheme sensitivity** to
`05_robustness.ipynb` after the existing Section 10C (prompt sensitivity,
cells 37–39) and before the export cell (cell 40).

The section calls `_address.assign_framing_lenses()` directly — but because
Part A adds a canonical-file bypass, we must temporarily move or rename the
canonical file before each run so the LLM path is exercised. The cleanest
approach is to expose a `_generate_raw_lens_grouping()` helper (or accept a
`force_llm=True` flag) that skips both the canonical and the outputs-cache and
always calls the LLM.

**Code cell:**

```python
# @title Lens-scheme sensitivity analysis (M6e)
import json, shutil, tempfile
import pandas as pd
import numpy as np

N_RUNS = 5
TECH_COL = "technology_meta"
ai_techs = ["AI"]
non_ai_techs = sorted(t for t in concerns_df[TECH_COL].dropna().unique() if t not in ai_techs)

records = []
for run_idx in range(N_RUNS):
    show_status(f"Lens sensitivity run {run_idx + 1}/{N_RUNS}...")
    # Force fresh LLM call (bypass canonical + output cache)
    raw_lenses = _address.generate_lens_grouping(
        cluster_exemplars, cluster_labels, kind='concern', client=client
    )
    for lens in raw_lenses["framing_lenses"]:
        mask = concerns_df["cluster_id"].isin(lens["suggested_clusters"])
        n_ai   = (mask & concerns_df[TECH_COL].eq("AI")).sum()
        n_ai_total = concerns_df[TECH_COL].eq("AI").sum()
        ai_share = n_ai / n_ai_total if n_ai_total else 0
        nonai_avg = np.mean([
            (mask & concerns_df[TECH_COL].eq(t)).sum() / concerns_df[TECH_COL].eq(t).sum()
            for t in non_ai_techs if concerns_df[TECH_COL].eq(t).sum() > 0
        ])
        records.append({
            "run": run_idx, "lens_name": lens["name"],
            "ai_share": ai_share, "nonai_tech_weighted": nonai_avg,
            "ai_minus_nonai_pp": (ai_share - nonai_avg) * 100,
            "n_clusters": len(lens["suggested_clusters"]),
        })

lens_sens_df = pd.DataFrame(records)

# Per run: find the lens with highest AI share (proxy for "most privacy/data-like")
summary = (
    lens_sens_df.sort_values("ai_share", ascending=False)
    .groupby("run").first()
    .reset_index()[["run", "lens_name", "ai_minus_nonai_pp"]]
)
summary["direction"] = summary["ai_minus_nonai_pp"].apply(
    lambda x: "over-indexed" if x > 0 else "under-indexed"
)
consistent = (summary["direction"] == "over-indexed").sum()
print(f"Direction consistent in {consistent}/{N_RUNS} runs")
print(f"pp range: {summary['ai_minus_nonai_pp'].min():.1f} to {summary['ai_minus_nonai_pp'].max():.1f}")
print(summary.to_string(index=False))

summary.to_csv(OUTPUT_FOLDER / "lens_sensitivity_summary.csv", index=False)
lens_sens_df.to_csv(OUTPUT_FOLDER / "lens_sensitivity_all_runs.csv", index=False)
show_complete("Lens-scheme sensitivity written to outputs/")
```

This requires a new public method `generate_lens_grouping()` on `AddressStage`
in `pub_dialogue/address.py` that always calls the LLM (no cache). The existing
`assign_framing_lenses()` continues to apply the canonical-first, cache-second,
LLM-fallback logic for the main pipeline.

## Backward Compatibility

- `outputs/framing_lens_mappings.json` and `outputs/benefit_framing_lens_mappings.json`
  continue to be written by the existing pipeline exactly as before; downstream
  cells and the robustness notebook continue to load them via `load_artifacts()`.
- `assign_framing_lenses()` is backwards-compatible: callers that do not have a
  canonical file present get the existing cache-then-LLM behaviour.
- The canonical JSON files (`pub_dialogue/lens_mapping_canonical_concern.json`,
  `pub_dialogue/lens_mapping_canonical_benefit.json`) are new additions; no
  existing file is renamed or removed.
- The robustness notebook cell 1 (`load_artifacts`) is unchanged.
- All existing exports are unchanged; two new CSVs
  (`lens_sensitivity_summary.csv`, `lens_sensitivity_all_runs.csv`) are added.

## Testing Strategy

  LLM is not called and the loaded mapping is used (check log output).
- Run cell 36 with canonical file absent (rename it temporarily); confirm the
  LLM is called, outputs-cache is written, and the warning message is logged.
- Run Section 10D in the robustness notebook; confirm `lens_sensitivity_summary.csv`
