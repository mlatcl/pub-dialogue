# CIP-0014: Beginner Setup Guide for New Collaborators

## Summary

Non-technical collaborators — policy researchers, domain experts, analysts who
have not written code before — need to run the analysis notebooks on their own
laptops. The existing "Quick start" in `README.md` assumes familiarity with
Python, virtual environments, and the command line. This CIP introduces a
dedicated `SETUP.md` guide that walks a complete beginner from a fresh laptop
(macOS primary; Windows and Linux also covered) through every step needed to
run the notebooks, and adds a short pointer to it in `README.md`.

## Motivation

A policy colleague who co-created the analysis notebook needs to run it locally
on a Mac. They have no prior experience with Python, virtual environments, the
terminal, or API keys. The current README's
quick-start block is not usable for someone in that position: it presupposes
knowledge of `pip`, environment activation, and `.env` files without explaining
what any of those things are or why they matter.

More broadly, the project aims to be reproducible not just for developers but for
the policy stakeholders who commissioned it and who may want to re-run or extend
the work. Removing the technical barrier to local setup directly serves that goal.

## Detailed Description

### What changes

1. A new `SETUP.md` file at the repository root, written for a reader who has
   never opened a terminal before.

2. A short "New to Python?" paragraph added to `README.md` just above the
   existing "Quick start (local)" section, pointing to `SETUP.md`.

### Structure of `SETUP.md`

The guide follows a linear narrative — each section ends with a verifiable
outcome so the reader knows they can continue.

#### 1. Before you start
One-paragraph orientation: what Python is, why a terminal is needed, roughly
how long the setup takes (~20 minutes for a first-time install). Sets the
expectation that the process looks complicated but is just a checklist.

#### 2. Step 1 — Open the terminal
The terminal is the foundation for every step that follows; start here so all
subsequent commands are run in the same environment.

- **macOS** (primary): Spotlight → "Terminal"; or Finder → Applications →
  Utilities → Terminal. Brief tour: the prompt, what `$` means, how to run
  a command, how to abort with Ctrl+C.
- **Windows**: [instructions to be added]

#### 3. Step 2 — Install Python
All commands run in the terminal opened in Step 1.

- Check whether Python 3.10+ is already present: `python3 --version`
- **macOS**: download the installer from python.org (pkg file, standard macOS
  install wizard); note that macOS ships with an old Python 2 that cannot be
  used
- **Windows**: [instructions to be added]
- Verification step: `python3 --version` should print `3.10` or higher

#### 4. Step 3 — Get the project files
All commands run in the terminal.

- Brief explanation of what git is (a version-control tool that tracks changes
  and lets you pull updates)
- Check whether git is installed: `git --version`
- **macOS**: git is usually pre-installed; if not, macOS will prompt to install
  Xcode Command Line Tools when you first run `git` — accept and wait
- **Windows**: [instructions to be added]
- Clone the repository: `git clone https://github.com/mlatcl/pub-dialogue.git`
- `cd pub-dialogue` to enter the folder; `ls` to confirm `README.md` is present
- Tip: `git pull` fetches future updates

#### 5. Step 4 — Create a virtual environment
Explain what a virtual environment is in plain English: "a private, isolated
copy of Python just for this project, so that installing packages here does not
affect anything else on your laptop."

```
python3 -m venv .venv
```

- Note: on Windows, use `python` instead of `python3` if the above fails
- The `.venv` folder is created inside the project; it is gitignored so it will
  never be accidentally uploaded

#### 6. Step 5 — Activate the environment
```
# macOS / Linux
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1
```

After running this, the terminal prompt gains a `(.venv)` prefix. Explain that
this prefix is the signal that the environment is active — every `pip install`
and `python` command now targets the project's private Python, not the system
one. They will need to run this activation command every time they open a new
terminal window.

#### 7. Step 6 — Install the project packages
```
pip install -e ".[dev]"
```

Explain: "This tells Python's package manager to install all the libraries this
project needs. It may take a few minutes and will print a lot of text — that is
normal." Note the quotes are required on macOS/Linux; on Windows PowerShell they
are also required.

#### 8. Step 7 — Get an API key
The notebooks call OpenAI's API to extract concerns and benefits from text.
An API key is a password that proves to OpenAI that requests are coming from a
specific account.

- Go to [platform.openai.com](https://platform.openai.com), create an account
  or sign in
- Navigate to API keys → "Create new secret key"
- Copy the key immediately (it is only shown once)
- **Billing note**: the full processing run (01_processing.ipynb) will use
  roughly $2–5 of API credit; subsequent notebooks do not call the API because
  they load pre-computed outputs. Add a small credit (e.g. $10) to the account
  before running for the first time.

#### 9. Step 8 — Configure the .env file
```
cp .env.example .env          # macOS / Linux
copy .env.example .env        # Windows
```

Open `.env` in a text editor (TextEdit on macOS, Notepad on Windows), find the
line `OPENAI_API_KEY=sk-...` and replace `sk-...` with the key copied in step 7.
Save the file.

Callout box: ".env is a private file that holds your secrets. It is already in
.gitignore, which means git will never upload it. Do not share it with anyone or
paste it into Slack, email, or a notebook."

#### 10. Step 9 — Launch Jupyter and run the notebooks
```
jupyter notebook
```

This opens a browser tab showing the project files. Click `01_processing.ipynb`
to open it. Run cells one at a time with Shift+Enter, or use the "Run all" menu
option. The first run calls the API and saves results to `outputs/`; subsequent
notebooks load those results and run much faster.

Alternative: open the project folder in VS Code, install the Jupyter extension
if prompted, and run notebooks from there.

#### 11. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `python3: command not found` | Python not installed or not on PATH | Re-run installer; on Windows ensure "Add to PATH" was ticked |
| `(.venv)` not shown in prompt | Environment not activated | Re-run the `activate` command from Step 5 |
| `ModuleNotFoundError: No module named 'pub_dialogue'` | Packages not installed, or venv not active | Activate venv then re-run `pip install -e ".[dev]"` |
| `AuthenticationError` from OpenAI | API key missing or wrong | Check `.env` has the correct key with no extra spaces |
| `jupyter: command not found` | Packages not installed or venv not active | Same as ModuleNotFoundError fix above |
| Permission denied on `.venv\Scripts\Activate.ps1` (Windows) | PowerShell execution policy | Run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once, then retry |

### Key design principles

- Plain English throughout: no assumed knowledge of the command line, Python, or
  web APIs
- Every command on its own line in a code block, ready to copy-paste
- Each step ends with a verifiable outcome so the reader knows when to proceed
- macOS is the primary narrative voice; Windows and Linux differences are shown
  as clearly labelled alternatives, not parallel documents
- Explain *why* each step is needed in one sentence, not just *what* to do
